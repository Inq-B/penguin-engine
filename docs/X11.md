# Native X11 backend (experimental)

The `penguind-x11` binary runs the real Wallpaper Engine rendering runtime
on X11. It is **not** the earlier external `scene-viewer` launcher.
The normal `penguind` executable selects it automatically when
`XDG_SESSION_TYPE=x11`.

## Install

Install `libX11`, `libXext`, `xrandr`, the graphics drivers, and the
normal dependencies for this workspace. On Arch/EndeavourOS:

```sh
sudo pacman -S --needed libx11 libxext xorg-xrandr
cargo install --path apps/penguind --bins --locked
cargo install --path apps/penguinctl --locked
```

`cargo install --bins` is essential: both `penguind` and
`penguind-x11` must be installed in the same directory.

Run `penguind 3566329932`, or start the systemd user service, then use
`penguinctl status`, `penguinctl set ...`, `penguinctl pause`, etc.
The saved wallpapers and user settings use the same JSON paths as Wayland.

## Implementation details

* One Xlib/EWMH desktop window and one wgpu surface per active RandR output.
* Detects monitor moves, resizes, hotplug and unplug approximately every 2s.
* Shared `wpe-runtime` for scene/video/web, `wpe-render` GPU device,
  `preset.rs` for Workshop presets and `state.rs` for persistence.
* Unix control socket with status, set, pause, resume, fps, fill, audio,
  volume, wallpaper volume, properties, settings, reload, quit and status
  subscription. Changes propagate to the running renderer.
* New X11 installations start click-through to preserve desktop icons.
  **Settings → General → Interactive wallpaper clicks** enables buttons.
  The choice is saved across restarts, and `--interactive`/`--passthrough`
  override it only when explicitly supplied. Pointer hover works in either
  mode. Xlib ButtonPress/Release events are forwarded directly where possible.
  On desktops such as Cinnamon/Nemo that cover the wallpaper window, the
  daemon also samples mouse button transitions over the desktop and forwards
  them to scene/web wallpapers, without forwarding clicks from regular
  application windows. Mouse wheel forwarding depends on X11 event delivery.
  **Caveat:** clicks over Nemo desktop icons may also activate the wallpaper;
  use click-through mode for desktop-only interactions.

## Known gaps and risks

This is an initial native X11 port, **not yet feature-parity with Wayland**:

* X11 window-state/fullscreen/idle rule signals are not implemented.
  `penguinctl signals` therefore returns an explicit error.
* Drag and other advanced pointer-gesture support is not complete.
  The desktop-only button-mask fallback samples input at render cadence,
  so extremely brief clicks may be missed if X11 sends them only to Nemo.
  Wheel input over Nemo's desktop is not globally intercepted.
* Current desktop windows use EWMH desktop stacking; desktop icon managers
  (including Nemo on Cinnamon) may paint above the wallpaper. That behaviour
  varies by window manager. This needs testing and potentially a dedicated
  desktop-manager integration.
* The interactive mouse fallback needs live Cinnamon/Nemo testing.
  Automated CI does not validate event routing or desktop stacking.
* X11 inherits the existing wgpu/renderer support limitations, and web
  wallpaper support depends on the `web` Cargo feature.

Avoid launching both the Wayland and X11 daemons: both use the same control
socket and persistence store.

## Multiple monitors and spanning (X11)

The GUI's **Settings > Displays** panel provides two layouts:

- **Separate displays** (default): each XRandR output has its own desktop
  window, wallpaper, and GPU surface. **Apply to all displays** shows the
  same item on each screen. Changes made through the GUI's wallpaper property
  editor are broadcast to all active screens showing that item when the
  target is **All displays**; targeting one display edits that display alone.
- **Span one wallpaper across all monitors**: when two or more monitors are
  connected, one desktop window and one wallpaper renderer cover their
  combined XRandR bounding rectangle. The daemon exposes a virtual output
  called `SPAN` to the GUI and control socket; selecting a wallpaper for
  `SPAN` fills the entire rectangle. Any gaps between monitors are part of
  the bounding rectangle. This is one scene or web page, not two copies.
  Disable the toggle to restore separate screen assignments.

The selection is persisted in the usual state file. The layout tracks monitor
changes at the X11 monitor scan interval (about two seconds). Spanning is an
X11 feature; Wayland compositors expose independent layer-shell surfaces and
do not currently support it.

## Property update pacing

The GUI batches changes in `set-properties`. Continuous input (sliders and
color pickers) is debounced: scenes wait longer than web wallpapers because
scene changes rebuild render resources. Releasing the control flushes the
latest value. X11 also coalesces on-disk state writes, instead of synchronously
writing `state.json` for every mouse event. Rapid multi-property changes are
applied in one scene rebuild or one web property update.


## Cinnamon lock-screen snapshot (X11)

Cinnamon's screensaver owns its own window and handles authentication;
Penguin Engine does **not** render behind or modify the unlock dialog.
Under **Settings → Displays**, enable **Lock-screen wallpaper snapshot**
to show a still image of the live wallpaper while Cinnamon is locked.
This is opt-in and requires `gdbus`, `gsettings`, a Cinnamon session bus,
and swapchain `COPY_SRC` support.

The daemon asynchronously reads an occasional frame directly from each wgpu
wallpaper surface, composes the physical monitor layout and writes
`~/.cache/penguin-engine/lockscreen.png`. It never includes regular
application windows. Updates are infrequent (approximately 90 seconds), not
live animation. When Cinnamon emits `org.cinnamon.ScreenSaver.ActiveChanged`,
the daemon temporarily points Cinnamon's background URI at this PNG, saving
and restoring its previous URI, picture style and slideshow setting on unlock.
The default background is untouched while the session is unlocked.

Caveats: Cinnamon may add its own blur/dimming; the wallpaper cannot remain
interactive or animated while locked. The first snapshot must finish before
the first lock event. If Cinnamon does not emit its usual D-Bus signal, the
image will not be applied. The GPU backend must allow swapchain readback.
